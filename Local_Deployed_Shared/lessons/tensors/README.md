## Invariants & Constraints
- 🔴 **Every function in a drill's solution or problem must be taught by a concept at or before it, and must appear in the ARENA corpus.** Both are enforced by this folder's `watch.py` via `scripts/guard_checks.py`, scoped to `torch.` (ids were `numpy.` until 2026-09-18), as ratchets against `scripts/solution_prereq_baseline.json` and `scripts/arena_grounding_baseline.json` — they fail on NEW debt only. Re-recording a baseline admits debt rather than paying it.
- **One dialect per page, and it must match the drills it fades into.** A page teaching `np.repeat` while its exercise grades `t.repeat_interleave` still passes every test and simply confuses the learner, so `watch.py` compares each KP's fence imports against the `answer_code` of every question id in its frontmatter. Convert a lesson and its bank questions in the same pass.
- **A KC the target dialect cannot express is RETIRED, not half-converted.** `numpy.structured-dtypes` taught record dtypes, `datetime64` and `genfromtxt`; a tensor holds one dtype for every element, so there is nothing in torch for those ideas to become. Inventing a torch-flavoured stand-in would have taught a NumPy idea in a dialect that cannot hold it, and leaving the page in NumPy would have re-broken the one-dialect rule above. So the page was `git rm`'d, its 6 drills (3, 55, 83, 96, 125, 157) were retired through `This-Directory-Only/chatgpt/function_mode_deleted_ids.json`, its rows were dropped from `../qmatrix_tags.json` and `../kc_registry.json`, and `../watch.py`'s KC floor moved 64 → 63 with the reason recorded beside the constant. Do the same four things together if another KC ever has to go: a registry entry with no page, or tags pointing at ids the bank no longer holds, fails `watch.py`.
- One concept per segment; exactly ONE worked example per segment; every segment has a faded exercise whose solution passes bank tests.
- Concept prose teaches the GENERAL procedure before the example (never example-only).
- Fences execute top-to-bottom in a shared namespace per file — later segments may rely on earlier definitions, so don't reorder segments without re-validating.

## Known Issues, Recurring Bugs, and Pain Points (and How to Prevent Them)

- **Faded starter written against assumed contract** — `ACTIVE`
  - When it happens: promoting a guided/independent qid to faded without reading its test_cases.
  - Symptom: validator FAILs the solution (e.g. q64's tuple order is (allclose, array_equal), not the "obvious" order).
  - Root cause: question text/tests differ from what the prose suggests.
  - Prevention/fix: always dump the bank question's test_cases first; let the validator be the gate.

- **Exact float equality in a torch fence** — `ACTIVE`
  - When it happens: writing `assert x.tolist() == [0.1, 0.4, 0.9]` in a converted KP.
  - Symptom: `validate_lessons.py` reports `fence failed: AssertionError` with no further detail; the code is correct.
  - Root cause: torch's default float is **float32**, so `0.4` round-trips as `0.4000000059604645`. NumPy's float64 hid this.
  - Prevention/fix: use dyadic values in worked examples (0.25, 0.5, 0.75, 3.5, 9.5 — exact in binary), or assert with a tolerance. The grader itself is tolerant; only the lesson fences use bare `==`.

- **A local variable named `t` shadows the torch alias** — `ACTIVE`
  - When it happens: converting a page whose maths uses `t` as a name — an angle, a time, a threshold, a transform matrix.
  - Symptom: the fence dies with something unrelated-looking like `AttributeError: 'Tensor' object has no attribute 'sqrt'` on the NEXT line, because `t` is no longer the module.
  - Root cause: `import torch as t` is the ARENA convention, so the alias occupies a very ordinary one-letter name.
  - Prevention/fix: rename the variable before translating, not after (`theta`, `m`, `cutoff`). The drill generator does this through its `SHADOW_RENAMES` table for the bank side; the page has to be renamed by hand and the starter's blank renamed with it, or the faded exercise stops matching its solution.
