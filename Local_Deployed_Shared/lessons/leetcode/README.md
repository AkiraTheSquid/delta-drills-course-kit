# leetcode

## Purpose
- The LeetCode Patterns course as the app serves it: coding-interview problems
  grouped by Grokking pattern (two pointers, sliding window, tree DFS, DP...).
- A standalone course with NO lesson pages: learners enable it on the Courses tab
  and practise drills straight away.

## Owns
- `problems.json`: every LeetCode drill, as flat rows in `questions.json`'s shape.
- `ids.json`: problem id → question id (60000+), append-only.
- `concepts.json`: the Knowledge Graph's page for each concept (the course has no
  lessons), generated by `scripts/leetcode_course/export_concepts.py`.

## Does NOT own
- The course's concept graph, the problem bank and difficulty ratings. They live in
  `This-Directory-Only/leetcode_course/` and are built by
  `This-Directory-Only/scripts/leetcode_course/`.
- The `leetcode.*` rows in `../kc_registry.json` / `../qmatrix_tags.json` and the
  `lc-*` atoms in the backend concept graph. `export_app.py` writes them next to
  this folder but they are shared files.
- The on/off switch: `backend/app/course_registry.py` (`course_off`) and
  `concept-graph/course-registry.js`.

## Key Files
- `problems.json`: generated drills; each carries `leetcode_kc`, `concept_title`,
  `test_cases` (`setup_code` / `call` / `expected_expr`) and `provenance`.
- `ids.json`: stable id map. Never renumber it.
- `concepts.json`: `{kcs: {<kc>: {title, description_markdown, drills, by_difficulty,
  examples}}}`. Text comes from `This-Directory-Only/leetcode_course/concept_notes.md`;
  edit it there and re-run `export_concepts.py`, never here.
- `watch.py`: id-range, id-stability, grader-shape and registered-concept checks, and
  every registered concept has a description in `concepts.json`.

## Data & External Dependencies
- Problems come from LeetCodeDataset (dataset asserts become test cases). NeetCode
  250 / Striver problems without a dataset row have their outputs generated by
  running two agreeing reference solutions.
- Difficulty is TypeSafe (Jev) pairwise rating per concept.
- Consumed by `pipeline/export_questions_json.py::load_leetcode_questions` (static
  bank) and `backend/app/leetcode_questions.py` (served bank).

## How It Works (Flow)
1. `scripts/leetcode_course/export_app.py` (backend venv) reads `bank.jsonl`,
   builds each drill and grades it: the reference must pass every case and the
   bare starter must fail one. Only then are the drills written here.
2. The same run rewrites the `leetcode.*` registry rows, the qmatrix slice,
   `glossary.js` kcLesson lines, the placement clock caps, the `lc-*` atoms and
   edges, and the atom tags.
3. Then run `scripts/build_qmatrix.py`, `export_kc_atom_crosswalk.py`,
   `export_questions_json.py` and `audit_question_bank.py --gate`.

## Invariants & Constraints
- Question ids live in 60000–69999 (math owns 50000+). They are assigned once in
  `ids.json` and never reused.
- `ListNode` / `TreeNode` classes go in the STARTER header. The grader runs learner
  code before `setup_code`, so a class defined in setup would come too late for
  the signature. Runtime imports and test helpers go in `setup_code`.
- The first test case must not expect `None`: the bank audit reads it as a
  placeholder answer (`degenerate_expected`, blocking).
- A concept with zero drills is left out of the registry. A standalone course
  with a drill-less frontier node would leave the picker stuck.
- Lesson-less exemptions are prefix-keyed (`LESSONLESS_PREFIXES` in
  `scripts/audit_solution_prereqs.py`, `LESSONLESS_LESSONS` in `../watch.py`,
  `lessons.is_prelibrary`). A new lesson-less course must be added to each.

## Extension Points
- More problems: extend the bank in `This-Directory-Only/leetcode_course/`, then
  re-run `export_app.py`. New problems get new ids; old ones keep theirs.
- Thin concepts (below 8 drills): fast-slow-pointers, in-place-reversal,
  cyclic-sort, sorting-algorithms, merge-intervals, two-heaps, k-way-merge, mst,
  knapsack-dp, dp-lis. ordered-set has no drills yet.

## Known Issues, Recurring Bugs, and Pain Points (and How to Prevent Them)

- **LeetCode drills parked by torch-only serving** — `RESOLVED`
  - When it happens: backend boot with `torch_only_serving`.
  - Symptom: the course was enabled but 0 LeetCode drills were served.
  - Root cause: `is_prelibrary` read `_kc_gate_info`, which is built from lesson pages,
    and this course has none.
  - Prevention/fix: `is_prelibrary` matches the `leetcode.` prefix.
  - Status: RESOLVED 2026-09-25.
